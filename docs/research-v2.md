# Research pipeline v2

Research remains server-side, bounded, research-only unless generation is explicitly enabled, and uses no search API or model to discover URLs.

Discovery retains ordinary anchor text, navigation aria labels and Markdown labels. Developer/API destinations and OAuth setup outrank marketing; generic marketplace exploration and localized HTML sitemaps each have one-page branch caps. Nested XML sitemap discovery retains the two-sitemap cap. First-party developer entry hosts may probe `/docs` and `/llms.txt`; these are unverified discovery attempts, and HTTP 200 soft-404 pages are rejected. HTML is preferred on navigation pages; Markdown is preferred on documentation paths. No scripts execute.

Limits remain 24 requests, 8 pages, 60 seconds total, 6 seconds/request, 3 redirects, 3 MB/response and 24,000 extracted characters/page. Probes, robots, redirects and delegated pages share those budgets.

A first-party page can delegate an exact documentation URL on a provider-named external tenant when the link explicitly identifies developer documentation. Explicit sibling documentation links can extend that chain, on the same delegated origin only, up to four exact URL grants. Grants never allow a host or a path prefix. Unrelated domains, lookalike nesting, unlinked destinations, out-of-scope redirects and rel=nofollow links are rejected. Every destination still receives public DNS/IP pinning, robots and publisher checks. Preparation replays recorded links and successful parent retrievals before accepting external evidence. The user-supplied provider website asserts the starting identity; this is link provenance, not independent legal ownership verification. Unclear or differently branded documentation hosts require explicit developer URL input.

New extraction uses versioned `blocks-v3` evidence; historical blocks-v2/legacy research registries remain independently checked by their original extractor. New candidates exclude metadata, navigation-only links and HTML/MDX table/callout fragments rather than repairing quotations. Complete sections across the whole bounded research text compete for lifecycle slots. Preparation retains original text privately for exact-offset/context validation; source summaries retain the existing 12,000-character limit. The model receives selected excerpts/context only, bounded by 36,000 evidence characters, 12 excerpts/source and 5 sources. Original text is stripped from returned generation source records.

Keyword coverage is a discovery/selection aid, not semantic verification. Oversized blocks, documentation beyond the 24,000-character research cap, inaccessible pages and ambiguous delegation can still leave gaps. Approval timing and recovery instructions remain unknown unless established by selected evidence. Neither research nor generation tests an OAuth connection.

Offline regressions: `npm test`. Live research acceptance uses `researchProvider` followed by `prepareGeneration`, without importing the model transport or reading credentials. Artifacts from acceptance belong outside saved-guide storage. No static guides, UI, storage or billing settings change.

## Bounded URL-pattern fallback

Link discovery remains primary. After an accessible initial page permits discovery, the crawler schedules a fallback only when neither a successfully retrieved documentation-shaped page nor an unvisited, non-pattern documentation candidate exists. A working linked developer entry therefore suppresses this fallback, even if its OAuth instructions still need discovery. Failed linked destinations can allow fallback once promising candidates are exhausted. Restricted, inaccessible and soft-404 initial pages do not activate it.

The candidates are HTTPS `developers.<established-domain>/`, `developer.<established-domain>/`, `api.<established-domain>/`, `<established-domain>/docs` and `<established-domain>/developers`. They are deduplicated against all queued/visited URLs, scheduled once, and run before lower-ranked generic branches. They are attempts, not asserted documentation. No provider-name domain guessing or cross-domain trust grant is added.

Pattern retrieval reuses the same queue, `retrieve`, robots policy, DNS/IP pinning, safe redirects and extraction. Its ten-request sub-allowance includes robots and redirects; the original 24-request, eight-page and 60-second global ceilings still apply. Linked follow-up pages use the same global budget. Remaining guesses are skipped once a documentation-shaped retrieved page contains OAuth/credential/token evidence. Pattern redirect destinations already attempted are not fetched again.

`ResearchResult.patternFallback` reports scheduling, deduplicated candidate URLs, attempted candidate URLs and attributable request count. `ResearchPage.discoveryMethod: pattern-probe` distinguishes a guessed entry from an actual source link. Unknown provider names still require an official website. Same-domain/public accessibility is not independent legal ownership verification; successful candidates still need useful source content, strict evidence preparation and human review.

These probes may consume time and request capacity without finding documentation. Successful documentation-shaped landing pages can suppress fallback without proving OAuth completeness. Offline tests cover success, link-first suppression, failures, URL safety, restrictions, limits and deduplication.

Pattern-fallback acceptance (2026-11-06): 132 offline tests, TypeScript and production build pass. The synthetic no-link case makes one pattern candidate attempt (two attributable HTTP requests including robots), follows its OAuth link and skips the other guesses. Failure fixtures attempt at most five candidates and ten attributable requests. Final public research-only runs: Pipedrive 15 requests/8 pages/3 prepared sources/20 selected excerpts; HubSpot 21 requests/8 pages/5 prepared sources/33 selected excerpts. Both skip the new five-pattern fallback (zero attempts/requests), preserving link-first discovery and late renewal evidence. Pipedrive source counts differ from the previous 4/28 because the live HTML sitemap navigation changed (1346 to 1875 links), replacing one marketing discovery page; its actual OAuth API reference and delegated setup text remain identical. HubSpot's source counts and retained evidence are unchanged. Registration completeness, review/timing and recovery gaps still require explicit unknowns and human review. No Gemini calls occurred.
